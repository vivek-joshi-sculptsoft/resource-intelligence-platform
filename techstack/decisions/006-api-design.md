# ADR-006: API Design

**Status:** Accepted
**Date:** 2026-06-09
**Deciders:** Engineering Team

---

## Context

The frontend (React SPA) needs to communicate with the backend (FastAPI) for all data operations. The data model is 14 entities with straightforward CRUD operations, list views with pagination/filtering, and role-based field visibility. The only API consumer is our own frontend.

## Decision

> We will use **REST** with OpenAPI 3.1 documentation auto-generated by FastAPI.

## Rationale

- The data model maps cleanly to REST resources: `/projects`, `/assignments`, `/resources`
- FastAPI auto-generates OpenAPI spec from Pydantic models — documentation is always accurate
- REST is the simplest pattern for CRUD with pagination and filtering
- TanStack Query on the frontend is designed for REST cache semantics (query keys = URL patterns)
- Single consumer (our React SPA) means no need for the flexibility GraphQL provides to multiple clients

## Alternatives Considered

| Alternative | Why Rejected |
|-------------|-------------|
| GraphQL | Adds resolver complexity, N+1 query risks, and a learning curve for a team building in one week. Benefits (flexible queries, reduced over-fetching) shine with multiple clients or deeply nested data — neither applies here. |
| tRPC | Requires TypeScript end-to-end. Our backend is Python. Not compatible. |
| gRPC | Designed for service-to-service communication. Requires proto definitions and grpc-web for browser clients. Overkill. |

## Consequences

**Positive:**
- Familiar pattern — no learning curve
- Excellent tooling: Swagger UI at `/docs`, ReDoc at `/redoc`
- TanStack Query cache invalidation maps directly to REST URL patterns

**Negative / Trade-offs:**
- Some views (project detail with assignments + costs + milestones) may require multiple API calls or a dedicated aggregate endpoint. Mitigated by creating view-specific endpoints where needed.

**Neutral:**
- URL versioning (`/api/v1/`) allows future API changes without breaking existing clients.

## Review Trigger

Revisit if a mobile app or third-party integration needs different data shapes from the same API.
